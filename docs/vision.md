## Vision / カメラ連携（CoreS3のみ）

このページでは、`StackChan_EX_Amigo` の Vision / カメラ連携について説明します。  

## 1. できること

Amigo版では、次の 3 系統のカメラ利用を扱えます。

- `見て` 系の発話で、一時確認として使う
- `撮影して` 系の発話で、資料としてローカルディスクに保存する
- AI 自身が必要と判断したときに、自動でカメラ確認に入る

ユーザー発話でも AI 判断でも `server` 側で Vision 解析して音声応答へ返します。

## 2. 全体の流れ

1. ユーザーまたは AI がカメラ利用を決める
2. M5Stack が撮影する
3. 画像を `server` の `/vision/upload` へ送る
4. `server` が Vision 解析する
5. 応答を音声化して M5Stack へ返す

構成としては、`firmware -> server -> Vision解析 -> push音声` です。

## 3. ユーザー発話での利用

ユーザー発話では、主に次の 2 モードを使い分けます。

### 3.1. 通常応答モード

撮影画像はその場の確認にだけ使い、処理後に削除します。
初期登録キーワード: 見て,みて,これ見て,みてみて,見てください,みてください

- 一時保存先: `VISION_DIR`
- 既定値: `/tmp/stackchan_vision`

### 3.2. 画像保存モード

画像とメタ情報をローカルへ保存します。

初期登録キーワード: 資料用に撮って,撮影して,写真撮って,写真を撮って

- 保存先: `VISION_ARCHIVE_DIR`
- 画像: `vision_*.jpg`
- メタ情報: `vision_*.json`

メタ情報には、撮影時刻、要求元、発話内容、Vision 解析結果、AI 応答などが入ります。

## 4. AI 発のカメラ起動

AI が「見ないと答えにくい」と判断した場合は、自分でカメラ起動を要求できます。

例:

- `これ何？`
- `これって何に使うの？`
- `同じもの？`

この場合は、`SD カード上のCash音声` を鳴らしてから撮影へ入ります。

- `vision_ai_trigger.mp3`

流れは次のとおりです。

1. AI が視覚確認を要求する
2. `server` が cue 音声を StackChan に送る
3. `server` が M5Stack の `/camera/trigger` を呼ぶ
4. 撮影画像が `server` にアップロードされる
5. Vision 応答を LLM で調整、音声化して返す


### 5. 会話ログ

Vision の利用履歴は、通常の会話と同様に `today.md` 側にも記録されます。  
一時確認か資料保存か、Vision 応答がどうだったかを後から追えるようにしています。

## 6. 主な設定

`ConfigUI` では、Vision まわりの次の調整ができます。

- 通常応答モードのトリガーワード
- 資料保存モードのトリガーワード
- 資料画像の保存先
- Vision モデルの変更
- SD カードに登録するCash音声の生成
