# 入力モード（ドラフト）

> 2026-09-11時点の操作・導入ドラフトです。実装済みの挙動と、まだ評価中の機能を分けて記載しています。

CoreS3では、顔のタッチ領域を長押しして、会話の入力方法を **タッチ** と **いつでも** から選べます。

| モード | 会話の始め方 | 一回の応答後 |
| --- | --- | --- |
| タッチ | 顔へ触れる | 次のタッチを待つ |
| いつでも | 選択した時点で待受開始。毎回のウェイクワードは不要 | 再生完了をserverへ通知して次の録音へ進む |

## モードを選ぶ

1. 顔のタッチ領域を2秒長押しする。
2. `タッチ` と `いつでも` の2ボタンが表示されたら、いったん指を離す。
3. 選びたいボタンへ新しく触れる。

長押ししたままボタンへ滑らせても選択されません。黒い余白、ボタンの間、複数指に触れた場合も、全ての指を離してから選び直します。

どちらのモードからでも同じ長押し操作で切り替えられます。選択はRAM上だけに保持し、NVSやSDカードへ保存しません。別アプリへ移ると `いつでも` は停止し、AiStackChanへ戻っただけでは自動再開しません。

## タッチ

従来どおり、顔へ一度触れると録音、STT、会話、TTSを一回実行します。カメラ、歌、検索が入った場合も、処理後は次のタッチ待ちへ戻ります。

`タッチ` を明示的に選ぶと、`いつでも` のserver sessionと本体の自動入力を停止します。従来のSimpleVox／文字ウェイクワード設定は残りますが、この選択中は自動待受を行いません。

## いつでも

`いつでも` を選ぶと、firmwareが `POST /v1/conversation/events` の `schema_version: 2` でsessionを開始します。開始に成功すると、既存の約3.75秒WAV録音を順番にSTTへ渡します。

- 音声が認識されたときだけ `speech` eventを送る。無音やタッチによる録音中断では、エラー音声や会話履歴を作らない。
- 通常返答は、TTSの取得、MP3デコード、PCM送出、Speakerキュー排出まで確認してから `playback_completed` を送る。
- カメラや歌は、実際の処理結果を `action_completed` の `succeeded` / `failed` として通知する。
- 一時的なHTTP失敗では、同じevent IDと同じ本文だけを再送する。返答、撮影、歌を重複実行しない。
- 継続できないprotocol不整合では古いsessionを捨て、新しいIDで待受へ復帰する。古い発話やactionは再生しない。

カメラ、歌、検索の途中でも、選択済みの入力モードは変えません。成功・失敗の完了通知をserverが受理してから、`タッチ` は次のタッチ待ちへ、`いつでも` は次の録音へ戻ります。

### 現在の「いつでも」の境界

`WHISPER_VAD_MODEL`を設定すると、Silero VADが音声区間を判定します。短い発話や特定の単語を文字列で除外しないため、`うん`、`ごめん`のような実際の短い発話もSTT結果として扱います。

VADが判断するのは「人の声らしい区間があるか」までです。発話がStackChan宛てか、人間同士の会話かは判別しません。同梱の会話参加reducer／評価ラボはまだ `/v1/conversation/events` の応答判断へ接続していないため、VADを通った周囲の会話へ返事をする可能性があります。

また、録音、HTTP処理、再生は順次実行します。TTSや効果音の再生中はマイクを止めるため、連続無欠落の収録、再生中の割込み発話、AECを使うfull-duplex会話ではありません。

## 必要な設定

`いつでも` は次のfirmware設定を使用します。

```yaml
llm:
  type: 0
  base_url: "http://<server-ip>:5050"

tts:
  type: 2
  base_url: "http://<server-ip>:5050"

stt:
  type: 1
  base_url: "http://<server-ip>:5050"
```

- `stt.type: 1` のWhisper経路と `tts.type: 2` のOpenAI互換TTS経路が必要です。未対応のSTT/TTS、offline modeでは開始しません。
- `llm.base_url` のserverには、`/v1/conversation/events`と `schema_version: 2` のaction相関を実装した版が必要です。
- serverの `.env` で `WHISPER_CLI`、`WHISPER_MODEL`、`WHISPER_VAD_MODEL`を設定します。VADの詳細は [server連携](server.md#44-stt-関連) を参照してください。
- SDカードには `Copy-to-SD/stack_sd_audio/*.mp3` を `/stack_sd_audio/` へコピーします。画像失敗用の `vision_error.mp3` もFlashとは別に配置が必要です。

## 表示から原因を切り分ける

| 本体表示・server応答 | 確認する点 |
| --- | --- |
| `いつでも / おんせい せっていを / たしかめてね` | offline mode、`stt.type`、`tts.type` |
| `いつでも / せつぞく エラー` | `llm.base_url`、server起動、認証、HTTP応答 |
| serverが `unsupported schema_version` を返す | serverが旧版。v2対応版へ更新する |
| 無音は止まるが周囲の会話へ反応する | VADでは宛先を判定できない。現在の既知境界 |
| 画像失敗時に専用音声が鳴らない | SDの `/stack_sd_audio/vision_error.mp3`。欠ける場合は汎用`error`へ一度だけフォールバックする |

## 確認済み範囲

CoreS3へのFlash、v2対応serverとの短い実会話、STT／会話／TTS／再生完了eventの一周は確認済みです。本体・serverを合わせた自動テストでは、正常系、重複event、通信断、相関不一致、再生失敗、モード復帰を検査しています。

実機のカメラ・歌・検索を組み合わせた全経路、長時間連続運転、部屋や音量が変わったときの誤反応、実I2S／音響、物理SD上の全音声は別途確認が必要です。詳細なwire仕様と回帰境界は [FW-005記録](../doc/conversation-actions-2026-09-11.md) に残しています。
