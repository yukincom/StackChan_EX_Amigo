# 通常機能の確認とLINEログ（2026-10-25）

追記: 下に記録した終了時SIGBUSは、その後の[原因調査と修復](2026-10-25-native-shutdown-fix.md)で解消しました。後続の依頼で両版のpush・CI確認も許可されました。以下は修復前の検証時点の記録です。

## 完了条件の修正

旧環境を版検査で止めることと、通常の機能を維持して環境を更新することは別です。CI・fixtureの成功だけを、実モデル・実機の確認として扱いません。

専用更新worktreeでは、core/test用venvを退避し、既存の実運用依存195 distributionsを参照する `.venv` に切り替えました。Python 3.11.14、音声・画像・モデル依存は維持し、ローカルにpip 26.2.2 / certifi 2026.10.23を導入。最低版検査は外していません。

このvenvは既存pyenvのsystem-site-packagesを参照し、独立した再現環境ではありません。元環境の依存は変更しません。実運用環境をlockで作り直す場合は、extrasだけでなく、使用中のモデル・辞書・手動導入packageも事前に確認し、別環境で同じ機能を確認してから切り替えます。検査用core/testのsyncで通常機能を削ってよいという意味ではありません。

## 変更

既存RenderポーリングのLINE受信時にも、Discordと同様に既存標準出力へ新着内容を出します。名前は既存のマスクを通し、user IDは出さず、改行をエスケープします。通知なし・通常timeoutではログを増やしません。

取得先、timeout、間隔、既存の配送台帳・音声・記憶処理は維持。API route、設定経路、起動方法、UI、常駐サービスは追加しません。

## 検証とその範囲

- 全体試験: **357 passed、skipなし**。実機・既存サービスには接続しない自動試験です。LINE受信ログの4件を含みます。
- 実際の公開版の会話・要約関数を、既存設定のローカルOpenAI互換8080で実行し、空でない回答と正常終了を確認。Gemini等を新規利用していません。
- 公開版のVOICEVOX/Kokoro関数を既存の実provider・cached modelで実行。日本語約2.65秒・英語約3.33秒、PCM16/24 kHzのWAV生成と正常終了を確認。fixtureではありません。追加のサーバーは起動していません。
- 通常別processで動くMLX関連・音声関連の全importと推論を1processへまとめた初回の一時検査では、結果出力後の終了処理でSIGBUSを記録しました。macOSレポートの停止箇所はsentencepiece内の `absl::Flag<bool>::~Flag()`。この混在検査を「正常終了」とは数えません。通常の会話・音声のprocess分離に合わせた上記2検査は終了code 0です。組み合わせと終了時エラーの因果関係は未確定で、この観測からPythonや既存library一式を無条件に入れ替えていません。
- 更新後bundleのCA拒否・通常TLSは、同じpip/certifi構成の家庭用実環境で確認。14監査chainをruntime/pipとも全件拒否、Requests/HTTPXの通常PyPI通信は両方200。
- 本体の発話・カメラ・通知・再生は、既存の家庭用GUI・家庭用serverを使ってユーザーが確認しました。公開版を本体へ切り替えた試験ではありません。

公開版への実機切替、Windows、別PCへの再構築は今回未検証。家庭用の設定・会話・写真・認証情報は公開版へコピーしません。ファーム・Flash・共有モデル・VOICEVOXの再起動は行いません。

変更は専用worktreeへローカル保存し、未コミット文書がある公開版本体フォルダは変更しません。今回の修復ではpush・公開・CI設定変更をしません。前回のCI成功を今回修正のCI成功とは扱いません。
