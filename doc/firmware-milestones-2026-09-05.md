# 本体改修の切り分けと検証状況

> 状態更新（2026-09-11）: 本稿は第4段階までの初期記録。その後、入力メニュー、`いつでも`、会話event v2、カメラ・歌・検索後のモード復帰を実装し、CoreS3へFlashした。現在の操作は [入力モード（ドラフト）](../docs/input-modes.md)、後続の詳細は [FW-005](conversation-actions-2026-09-11.md) を参照。

## 進める順序

1. **撮影modeの受渡し**: HTTP契約と保存判断。ラボとPythonテストで先に検証し、独立commitにする。
2. **夜間の待機顔**: 時計/待機/活動/明示指定のロジックをhostで検証し、描画の実機確認は後でまとめる。
3. **口パク**: 音量と開口率の変換・更新周期を分離。Avatar描画ライブラリは変更しない。
4. **電源診断は追加しない**: 既存の電池表示・Status Monitorを維持する。Serial専用の診断はユーザーの運用に合わないため撤回。
5. **操作の非同期化・中断/復帰**: 再生/撮影/録音の所有と処理単位を先に整理してから変更する。
6. **常時マイク経路とwatchdog**: 所有と復帰が固まった後で接続し、watchdog単純再有効化はしない。サーバーとの通信名称は事前に合意する。

これはcommit/原因切り分けの順序であり、項目ごとのFlashを依頼する順序ではない。
各段階で実機なしテストを行い、対応機種buildと復旧・実機確認手順をまとめてからユーザーへ依頼する。
