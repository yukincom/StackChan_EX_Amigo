# 名前の用途と会話構造を分ける実験

実Live回帰試験で候補が悪化したため、既定方式への採用は見送り。
外部研究の再調査と次の改善案は [参加判断と改善の仕組み](conversation-participation-research-2026-09-06.md) を参照。

## 仮説と一次資料

名前が文字列にあるかだけでなく、「誰について話しているか」「今の宛先」「何への返事か」を分けると、
名前への言及・引用による誤復帰を減らせるかを調べる。以下は設計の根拠であり、家庭内のQwenで同じ性能が出る証明ではない。

- [Chang et al., Multimodal Conversation Structure Understanding (2025)](https://arxiv.org/html/2505.17536v1): §4・付録A.1.1ではreply-toと宛先等の会話役割を区別する。付録A.1.5には速いやり取りで別人の発話が同じ文字起こし行に混ざる問題がある。映像・音声付きTV会話の研究で、家庭の匿名テキストとは条件が違う。
- [Penzo et al., Multi-Party Hangover (2024)](https://aclanthology.org/2024.emnlp-main.628.pdf): 会話構造と本文の利用を比較する。既知の構造や次話者を与える条件の成績を、構造自体を推定しなければならない本実験へ転用しない。
- [Inoue et al., An LLM Benchmark for Addressee Recognition (2025)](https://sap.ist.i.kyoto-u.ac.jp/lab/bib/intl/INO-IWSDS25a.pdf): 日本語の自然な3者対話では、本文を使ったGPT-4oのaccuracy 80.9%が多数派基準80.6%に近い。全体正解率だけでなく誤割込みと呼名取りこぼしを別に見る理由になる。
- [OpenAI Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices): 用途別の評価軸と人間の判断との照合を重視する。今回は正解注釈を推論入力から隔離し、開発結果と確認用結果を分ける。

## 最小の候補

既存baselineを残し、`--reader structured` のみで候補を使う。同じローカル通信、temperature 0、thinking無効、出力上限400 tokens。
候補は追加プロンプト分だけ入力トークンが異なる。使用量と経過時間は各行に記録する。

- `name_use`: direct_call / mention / quoted_call / other_call / none。
- `name_text`: currentに実在する名前の部分文字列。直接呼名は明示した登録名と完全一致が必要。
- `reply_to_id`: 見えている過去発話のID、または根拠がないときnull。
- `addressee`, `human_exchange`, `evidence_ids`: 現在末尾のやり取りを対象にする。

これを型・参照検証して既存Sceneへ変換する。矛盾した出力はエラーとして採点し、成功した沈黙に数えない。
参照が本文に存在することは意味理解の正しさを保証しない。話者の実名/家庭内役割や、確かな人数を推定して保存する機能ではない。
同じ行の前半で呼ばれていても、後半が人間同士の会話へ移っていれば末尾の宛先を判断する。
これは録音バッファ途中での即時停止を再現するものではない。

## 比較とデータ境界

`tests/fixtures/conversation_structure_cases.json` は全て創作。4対照群、各2内容、各々分割/連結版の16ケース・24入力に、
同じ回答文でも直前がassistantの質問かhumanの質問かを変える2ケースを追加。計18ケース・28発話（27入力を採点）。
開発用は言及対呼名・引用対実際の呼名、確認用は人間の回答対AI回答待ち・宛先が切り替わる順序。
同じ対照群を開発/確認の両方に入れない。候補の初回推論前に本文・ラベルを固定した小規模プローブであり、無作為標本でも独立した外部ベンチマークでもない。

追加のreply-to対照と構造ラベルは独立レビュー後、改訂候補v2の推論前に固定した。初回v1は16ケース版の開発用だけを使用。

採点はaction+mode、誤割込み、返答取りこぼし、解析エラー。分割版と連結版の末尾action+modeも照合する。
両版で同じ誤りを出しても一貫して見えるため、分割一貫性だけを合格基準にしない。
静聴から始まる単独の言及では人間同士の成立を断定せず、呼名がない限り静聴を保つことを採点する。

構造の正しさは `scene_fields` / `structure_fields` で別採点する。例えば返答actionが合っても、
`reply_to_assistant`、`reply_to_id`、mention/quoted_callを取り違えれば構造の得点は落ちる。
構造出力を持たないbaselineやoracleでは該当項目をmissingと表示し、Noneの正解として扱わない。
従来の `whole_case_pass` とexit codeは参加動作の一致を示すだけで、構造全体の合格を意味しない。

v1で誤った過去の名前の転記と重複参照の欠落が出たため、v2ではcurrentに名前がない場合を明確化し、
reply_to_idの存在検証とevidence_idsへの重複記入を分離した。未来/非表示IDは引き続き拒否する。
拒否されたJSONは新規の私的レポートに残すが、採点や次の推論へ正解として渡さない。失敗後の自動再試行はしない。

既存の実Live抜粋・製品名派生・登録名試験は非公開メンテrepoに置く。
以前に結果を見た保留ケースは今後は回帰試験扱い。改善後の未使用データ精度と呼ばない。
モデルが変わったら旧方式も同じモデルで再測定し、旧モデルの数字から実装効果を計算しない。

追加OSS/外部サービス/学習依存は導入していない。論文のデータセットやコードも転載していない。
既存pytestとプロジェクト固有の小さなアダプターを利用する。自動学習・個人化、本番接続、音声停止、Flashはこの実験の対象外。
