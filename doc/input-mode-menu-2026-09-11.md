# 顔の長押しによる入力メニュー

対象: CoreS3の本体作業ブランチ。旧UIの`03f8367`に続き、2ボタン版`d75a148`を2026-09-11にFlash済み。本稿末尾の吹き出し文字列・中央揃え修正はまだFlashしていない。

## 操作

- 顔の同じ場所を2秒長押しするとメニューを開く。
- 顔を隠し、大きな白いボタンを縦に2つ表示する。上は **タッチ**、下は **いつでも**。黒い40px日本語文字を縦横とも中央に揃え、見出しや説明文は付けない。
- 長押しした指をいったん離してから、どちらかのボタンへ新しく触れる。離すときではなく、新しく触れた瞬間に選択し、ボタンを消して元の顔へ戻る。成功時のモード名表示は残さない。接続失敗時は顔にエラーを表示する。
- 「タッチ」「いつでも」のどちらからも同じ顔長押しで、この2ボタンを再表示する。
- 開くための指離しと、選択した指の長押し・移動・指離しでは、追加の選択・録音・撮影・アプリ切替を起こさない。
- 黒い余白やボタン間への接触、複数指ではメニューを開いたままにする。その接触からボタンへ滑らせても選択しない。全ての指を離して新しく触れ直す。
- メニュー外では従来どおり、16pxを超える移動、複数指、受け付けた時点で本体が再生・撮影中の接触は長押し/タップとして確定しない。未処理の操作を予約しない。
- 「タッチ」での通常の顔タッチ、明示的な画像付き会話、メニュー外の左右フリックは維持する。「いつでも」での顔タッチはサーバーへ復帰イベントを送る。

## 確定した動作と接続状況

「いつでも」ON自体が会話開始の意思表示であり、毎回ウェイクワードを要求しない。人間同士の会話を見て黙る判断はサーバー側で行い、静聴後の名前での呼びかけ/顔タッチは復帰に使う。旧SimpleVox待受への単純な名前の付け替えではない。

- **タッチ**: 既存の顔タッチ→STT→会話を使用する。選択後はSimpleVoxと文字ウェイクワード双方の自動待受を停止し、開いているサーバー会話へ`stop`を送る。通信に失敗しても本体の自動入力はOFFになる。
- **いつでも**: `start`の成功後に待受を開始する。認識結果を新しいイベント経路へ送り、`reply`ならTTS、`listen`/`wait`なら発声しない。顔タッチで`face_touch`を送り、次の待受へ戻る。ONの再選択でセッションを作り直さない。旧`robot->chat()`や本体の会話履歴追加は通さない。
- 待受録音は既存の3.75秒WAV録音を順次使用する。録音中の接触はその録音を破棄し、メインループへ操作を返す。無音/操作による中断では「聞き取れません」を再生しない。認証・接続・再生・プロトコルエラーではタッチへ戻し、自動再試行しない。
- 既存wakeword設定・登録データ・起動時の設定適用は変更しない。旧ウェイクワード待受を新しい「いつでも」として扱わない。
- 選択はRAM上のみ。NVS/SDへの保存は追加しない。アプリを離れると「いつでも」を停止し、戻っても自動再開しない。旧ウェイクワードの明示的な有効化/登録は「いつでも」中には割り込ませない。

## 合意済みv1通信

サーバー公開版`a185a18`、家庭用`0d72c34`の受け口と読み合わせ済み。`POST /v1/conversation/events`を使う。

共通リクエストは`schema_version: 1`、`session_id`、`event_id`、`type`。IDはデバイス/ユーザーの識別情報を含まない乱数で、明示的な再ONごとに新しいセッションを作る。

| type | 追加値 | 本体の扱い |
| --- | --- | --- |
| `start` | なし | `active/listen`を確認して開始 |
| `speech` | 現在の`text` | `reply`は再生待ち、`listen`/`wait`は次の待受 |
| `playback_completed` | 応答の`reply_id` | 受理まで次のspeechを送らない |
| `face_touch` | なし | `active/listen`で復帰 |
| `stop` | なし | 本体は即OFF、`closed/stopped`を確認 |

- 応答の版、型、エコーID、状態/アクション、replyを検証する。409や応答取りこぼしでも自動再送・自動再発声をしない。
- `speech.text`はサーバー契約の1000 Unicode文字まで。超過は切り詰めず停止する。受信16KiB・送信8KiBは本体通信バッファの上限で、モデルの生成設定を変更するものではない。
- イベントのURL/キーは既存の`llm.base_url`/LLMキーを使用する。URL空欄から公開OpenAI APIへフォールバックしない。STT/TTSはそれぞれ既存の設定を使用する。
- 当初は試験時だけ`SC_ExConfig.yaml`の3つのbase URLを5052番へ揃える計画だったが、実際のFlash時には変更せず、既存5050番のままだった。2026-09-11の実機操作で`start`/`stop`が404になり、ライブ側へのイベント受け口の未適用が判明した。サーバー担当へ既存5050番で受けるための本番準備を依頼済み。ソースの準備完了と実際の稼働は別に確認する。本体設定を無断で5052番へ変更せず、IPもソースへ固定しない。

## 再生完了と未実装の境界

- 新経路はWhisperとOpenAI互換TTSラッパーを使用する。未対応のSTT/TTS設定では開始しない。通常のタッチ経路は既存バックエンドのまま。
- 再生完了は、MP3の有限Content-Lengthまでの受信、デコーダのEOF終了/エラー状態、PCM送出の成否、Speakerキューの排出でソフトウェア確認する。排出待ちは固定遅延ではなく最大2秒の期限。未知長・途中切断・デコード異常・送出失敗は成功ACKにしない。人に音声が聞こえたという音響的な証明ではない。
- サーバーの現commitではmemory/forecastが`process_chat`内で先に更新される。`playback_completed`は送受信順序の制御であり、記憶の再生後確定は未実装。TTS側の文字数処理を含め、reply全文が実際に読み上げられた保証も別の確認になる。
- 現サーバーはactiveのspeechを通常会話へ渡し、周辺会話の判別/quietへの移行/名前での復帰判定は未接続。本体に毎回のウェイクワード判定を追加することで代用しない。
- `stackchan_action`付きreply、内部`[[VISION_...]]`マーカーは音声化も成功ACKもせず、未対応表示で停止する。「タッチ」の既存カメラ会話は維持する。新経路のカメラ完了契約は今回追加しない。

## 実装上の境界

- `TouchGesture.h` は固定サイズの接触状態のみで、動的確保やタスクを追加しない。2秒の閾値、指離し、移動、複数指、busy、時刻の桁あふれをホストC++テストで確認する。
- 表示はAvatarの既存描画タスクとスプライトを再利用する固定座標の全画面オーバーレイ。顔の回転・倍率・位置ずれの影響を受けず、ボタン矩形とタッチ範囲を同じ定数から決める。320×240画面で白い範囲は上が`x=16..303, y=16..111`、下が`x=16..303, y=128..223`。新しい描画ライブラリ、画面バッファオブジェクト、並列音声バッファ、録音タスクは追加しない。
- `InputModeMenu.h`が指離し待ちと新規接触での選択を管理する。M5Unifiedは指離し情報を1フレーム残すため、メニューには`getCount()`ではなく`isPressed()`で数えた接触数を渡す。選択後もその指の接触全体を通常ジェスチャー側で消費する。
- タッチを処理してからidleを呼び、メニュー表示中/顔に触れている間は自動録音を開始しない。アラーム・スケジュールはこの抑止の外に置く。
- メニュー終了時に通常のカメラ表示/QR表示を戻す。idleで撮影/再生のbusyを検知した場合、アラーム発火時、アプリを離れる場合はメニューを閉じる。
- STT/会話HTTPとTTSは同期処理のため、その処理中はメニューを操作できない。録音・転送・返答の間には収録の隙間がある。TTS/効果音中は既存どおりMicを止める。無欠落の連続収録、割込み発話、AEC full-duplexは実装していない。
- Mac音声試験やホストC++試験は、実機のタッチ感度、描画、I2S、AEC、CPU/heap負荷の合格を意味しない。

## 実機報告後の吹き出し・中央揃え修正

`d75a148`で、モード選択後の不明な吹き出しとゴミ状の文字、および通常タッチ会話の返答から時間を置いた電源断が報告された。モード開始/停止の404と、通常タッチ経路のSTT/chat/TTSの200を確認した。電源断時のUSBログは取得できておらず、その原因は未確定。

- `stop_always_input()`がローカル`String`の`c_str()`を渡し、Avatarがポインタだけを保存していた。関数終了で文字列が破棄された後も、描画タスクがそのポインタを`strlen`や文字描画へ渡す寿命不具合を確認した。
- Avatar内の`SpeechText`が文字列のコピーを所有するよう修正した。各フレームはmutex保護下で独立した文字列を取得し、`Face → Balloon`の同期描画が終わるまで保持する。描画中はmutexを保持しない。`nullptr`は空文字として扱う。呼び出し側の文字列は設定呼び出し中だけ有効ならよく、既存のコピーAPIも維持する。
- 全ての`setSpeechText()`呼び出しへ適用するため、一時的なエラー文字列だけでなく、後で更新される文字列にも対応する。エラー内容の切り詰め、表示時間、通信仕様、SD設定は変更しない。長文・改行の吹き出しレイアウト改善は別問題であり、今回は含めない。
- M5GFXでは数値`4`が`middle_left`であり、旧テストも同じ誤った値を前提にしていた。実機アダプターで名前付きの`lgfx::textdatum_t::middle_center`を指定するよう修正した。ボタン矩形・タッチ範囲は変更しない。
- 一時文字列の破棄・再利用、フレーム取得後の更新/クリア、複数writer/readerの全文一致、コピーの独立性を本番`SpeechText`のホストC++試験で確認した。ASan/UBSanとTSanを別途有効にした同試験も成功。Avatarから描画への接続はソースレビューで確認しており、Avatar全体のホスト実行試験ではない。
- 中央揃えは本番`InputModeMenuView`を最小Canvasスタブで実行し、ローカル3機種分の実M5GFX enumヘッダーと照合した。ヘッダー未取得の環境ではこの追加試験のみskipする。`M5GFX_INCLUDE_DIR`でもヘッダーを明示できる。
- 修正後は全体136件、CoreS3/Core2/AtomS3Rの3機種ビルドが成功。既存依存ライブラリ由来の非推奨警告等は残る。修正前の復旧基点は`d75a148`。まだFlashしておらず、実機上の表示改善・連続稼働・電源断解消は未検証。
