# 顔の長押しによる入力メニュー

対象: CoreS3の本体作業ブランチ。実機へのFlashはまだ行わない。

## 操作

- 顔の同じ場所を2秒長押しするとメニューを開く。
- 開くために触れた指は、離しても選択・録音・撮影を起こさない。次のタップで選択する。
- 表示名は **タッチ / いつでも**。新しいメニューの文字はひらがな・カタカナにする。
- メニュー外、見出し、項目間の空白へのタップは閉じるだけ。メニュー中のフリックも閉じるだけで、別アプリへの移動を起こさない。
- 16pxを超える移動、複数指、受け付けた時点で本体が再生・撮影中の接触は長押し/タップとして確定しない。未処理の操作を予約しない。
- 通常の顔タッチ、明示的な画像付き会話、メニュー外の左右フリックは維持する。

## 確定した動作と接続状況

「いつでも」ON自体が会話開始の意思表示であり、毎回ウェイクワードを要求しない。人間同士の会話を見て黙る判断はサーバー側で行い、静聴後の名前での呼びかけ/顔タッチは復帰に使う。旧SimpleVox待受への単純な名前の付け替えではない。

- **タッチ**: 既存の顔タッチ→STT→会話を使用する。選択後はSimpleVoxと文字ウェイクワード双方の自動待受を停止する。録音ドライバーの開始停止やI2S構成は変更しない。
- **いつでも**: 上記の動作で確定。サーバー側の開始/終了/顔タッチ/発話の受け渡し契約を調整中。この段階のコードでは「せつぞくまち」と表示し、有効化しない。押した場合も録音や会話へ進まない。これは最終仕様ではなく、接続前の作業段階である。
- 起動時の既存wakeword設定・登録データは変更しない。旧ウェイクワード待受が動いていればメニューの現在値は「あいず」と表示し、「いつでも」が完成したと誤表示しない。
- タッチ選択はRAM上のみ。NVS/SDへの保存は追加せず、再起動後は既存設定に戻る。明示的な既存ウェイクワード有効化/登録の操作は維持する。
- サーバーとの新しいHTTP route、payload、参加状態名は追加していない。「名前で復帰後は毎回呼ばずに続く会話」と、既存の毎回ウェイクワードを待つ動作は別であり、未接続の参加reducerを実装済みとは扱わない。

## 実装上の境界

- `TouchGesture.h` は固定サイズの接触状態のみで、動的確保やタスクを追加しない。2秒の閾値、指離し、移動、複数指、busy、時刻の桁あふれをホストC++テストで確認する。
- 表示は既存AvatarのテキストSubWindowを使う。新しい描画ライブラリ、画面バッファオブジェクト、音声バッファ、録音タスクは追加しない。既存テキスト描画で必要となる一時スプライトの利用自体はある。
- タッチを処理してからidleを呼び、メニュー表示中/顔に触れている間は自動録音を開始しない。アラーム・スケジュールはこの抑止の外に置く。
- メニュー終了時に通常のカメラ表示/QR表示を戻す。idleで撮影/再生のbusyを検知した場合、アラーム発火時、アプリを離れる場合はメニューを閉じる。
- Mac音声試験やホストC++試験は、実機のタッチ感度、描画、I2S、AEC、CPU/heap負荷の合格を意味しない。

## 検証・復旧

- 本体向けhostテスト3件成功。Python unit全体100件成功。
- CoreS3/Core2/AtomS3Rの3機種ビルド成功（53.821秒、exit 0）。
- 実機では、通常タップ、2秒長押し→指離し→選択、メニュー内フリック、カメラ表示復帰をまとめて短く確認する。今回だけを理由に追加Flashを依頼しない。
- 改修前の復旧基点は `f41c328`。Flash済み版のバックアップとは別なので、実機に書く前にはその端末の復旧手段も確認する。
